# PRD: 카메라 작례 지도 서비스 (ShutterMap, 셔터맵)

- 문서 상태: v1.1 (MVP 범위 확정 + 아키텍처 결정 반영)
- 작성일: 2026-09-19
- 최종 수정일: 2026-10-06

---

## 1. 소개

카메라/렌즈 실사용 작례(샘플 사진)를 지도 위에 매핑해서 보여주는 서비스다. 사용자는 자신이 촬영한 사진을 업로드하면 EXIF(카메라 기종, 렌즈, 조리개, ISO, 촬영 위치 등)가 자동으로 추출되어 지도에 등록되고, 다른 사용자는 지역·장비 조건으로 필터링하며 "이 장비로 이 장소에서 찍으면 어떤 사진이 나오는지"를 탐색할 수 있다. 같은 데이터를 지도 대신 갤러리(목록)로도 볼 수 있어, 장소와 무관하게 특정 장비의 작례만 모아 볼 수도 있다.

두 가지 니즈를 하나로 묶는다:

- 장비 구매 전 실사용 샘플을 찾는 니즈 (해외 PixelPeeper류 서비스가 부분적으로 충족)
- 출사지(촬영 장소)를 발굴하는 니즈 (국내 사진 커뮤니티에 비공식적으로 존재)

사용자가 업로드하는 콘텐츠는 본인 촬영물이므로 원본 콘텐츠 저작권 문제가 발생하지 않는다는 전제로 설계한다.

---

## 2. 목표

- 사용자가 자신의 사진을 업로드하면 별도 입력 없이 EXIF 기반으로 지도에 자동 등록되는 경험을 제공한다.
- 카메라/렌즈 조건으로 필터링해 원하는 장비의 실사용 예시를 지도에서 바로 찾을 수 있게 한다.
- 지도와 같은 데이터로 카메라/렌즈별 작례를 목록(갤러리)으로도 볼 수 있게 한다.
- GPS 정보가 없는 사진도 수동 위치 등록으로 서비스에 참여할 수 있게 한다.
- 위치 정보 공개 범위를 사용자가 직접 통제하게 해 사생활 노출 리스크를 최소화한다.

**목표가 아닌 것 (Non-goals)**

- 사진 판매/거래 마켓플레이스 기능
- 사진 편집·보정 기능
- 실시간 촬영 위치 공유(라이브 트래킹)

## 3. 유저

| 유형 | 설명 | 핵심 니즈 |
|---|---|---|
| 등록자(Contributor) | 자신의 사진을 업로드하는 사용자, 대부분 카메라 보유자 | 내 장비/사진을 기록하고 노출하고 싶음 |
| 탐색자(Explorer) | 장비 구매 전 실사용 샘플을 찾거나 출사지를 찾는 사용자 | 조건(장비/지역)으로 사진을 빠르게 필터링하고 싶음 |
| 비로그인 방문자 | 링크로 유입되거나 지도와 갤러리를 둘러보기만 하는 사용자 | 로그인 없이도 지도와 갤러리를 열람하고 싶음 |

> 등록자와 탐색자는 배타적이지 않고 같은 사용자가 양쪽 역할을 겸할 수 있다.

**권한 정책**

- 비로그인 사용자는 지도, 갤러리, 사진 상세를 필터 포함 전면 열람할 수 있다.
- 업로드와 좋아요는 로그인이 필요하다. (소유자 없는 사진의 수정/삭제/공개 범위 변경 문제를 막기 위해 비로그인 업로드는 허용하지 않는다.)
- 등록자의 "보유 장비"는 필수 정보다. 가입 단계에서 강제하지 않고, 첫 업로드 시 EXIF의 카메라/렌즈로 미리 채워 확인받는다. 이로써 업로드 전에 보유 장비가 등록되도록 보장한다.

## 4. Flow

### 4-1. 사진 등록 플로우 (GPS 있는 경우)

```
사진 선택/업로드
  → EXIF 자동 파싱 (카메라/렌즈/조리개/ISO/GPS 등)
  → GPS 존재 확인 (Yes)
  → 위치 공개 범위 선택 (반경 흐리기[기본값] / 정확한 좌표 / 지도 미노출)
  → 미리보기 확인 (파싱된 EXIF 값 수정 가능, 첫 업로드면 보유 장비 확인)
  → 등록 완료 → 지도에 핀 생성 (지도 미노출이면 갤러리에만 노출)
```

### 4-2. 사진 등록 플로우 (GPS 없는 경우)

```
사진 선택/업로드
  → EXIF 자동 파싱
  → GPS 존재 확인 (No)
  → 지도에서 위치 수동 지정 (필수 단계, 건너뛸 수 없음)
  → 위치 공개 범위 선택
  → 미리보기 확인
  → 등록 완료 → 지도에 핀 생성 (지도 미노출이면 갤러리에만 노출)
```

위치 입력은 GPS 유무와 관계없이 항상 필수다. 위치는 항상 저장하고, 노출 여부는 공개 범위(기능 3)가 결정한다.

### 4-3. 지도 탐색 플로우

```
지도 진입
  → (선택) 카메라/렌즈/지역 필터 적용
  → 클러스터 핀 확인 → 줌인 시 개별 핀 분리
  → 핀 클릭 → 사진 상세 카드 (이미지 + EXIF + 촬영자)
  → (선택) 좋아요
```

### 4-4. 갤러리 탐색 플로우

```
갤러리 진입 (지도/갤러리 탭 전환, 필터 상태 공유)
  → (선택) 카메라/렌즈/초점거리/조리개 필터 적용
  → 정렬 선택 (최신순[기본] / 좋아요순)
  → 썸네일 그리드 스크롤
  → 사진 클릭 → 사진 상세 (기능 5)
```

## 5. STACK

- 백엔드: Node.js + NestJS (모든 API/비즈니스 로직 담당)
- 프론트: Next.js — 순수 UI 렌더링과 라우팅 전용. Route Handlers는 거의 쓰지 않고 API는 NestJS로 통일
- DB: PostgreSQL + PostGIS (`geography(Point, 4326)` 컬럼을 처음부터 사용. 나중에 추가하면 기존 row 전체를 백필해야 해서, 뷰포트 조회(기능 4)의 공간 인덱스가 필요해지는 시점을 기다리지 않고 지금 넣는다)
- ORM: Prisma
- 지도: 카카오맵 JS SDK (위치 검색은 카카오 로컬 API)
- 클러스터링: 클라이언트에서 supercluster (radius 60px, maxZoom 16 기준, 그 이상 확대 시 개별 핀)
- 인증: 이메일 + 소셜 로그인(카카오, 구글). 인증은 NestJS에서 전부 처리한다. 세션은 httpOnly 쿠키로 발급하고, Next.js는 그 쿠키를 자체 검증하지 않고 매 요청마다 NestJS의 세션 확인 엔드포인트(예: `/auth/me`)에 검증을 요청한다 — "인증 로직은 전부 NestJS"라는 원칙을 Next.js 쪽에서 깨지 않기 위함
- EXIF 파싱: exifr (HEIC 지원)
- 이미지 처리: 서버에서 HEIC 변환, 서빙용 리사이즈본/썸네일 생성, EXIF GPS 제거
- 이미지 저장소: Cloudflare R2 (원본 보관 + 서빙용 이미지)
- 플랫폼: 웹 전용 (모바일 브라우저 대응 포함)

### 5-1. NestJS 모듈 경계

기능 단위(1~9)로 모듈을 1개씩 나누지 않는다. 기능 2·3(위치/공개범위)은 기능 1(사진)의 속성이고, 기능 4·8(지도/갤러리)은 PRD 특이사항에 이미 "필터 조건과 API를 공유한다"고 적혀 있어, 같은 소유권으로 묶어야 로직 중복과 모듈 간 순환 의존을 피할 수 있다.

- `AuthModule` — 기능 6
- `PhotosModule` — 기능 1, 2, 3, 5 (업로드+EXIF, 위치, 공개범위, 상세를 하나의 Photo 엔티티 소유권 아래 서비스로 분리: `PhotoUploadService`, `PhotoLocationService`, `PhotoVisibilityService`)
- `DiscoveryModule` — 기능 4, 8 (필터 빌더 서비스 하나를 공유하고, `/discovery/map`과 `/discovery/gallery` 두 엔드포인트로 응답 방식만 다르게)
- `EngagementModule` — 기능 7, 9 (사용자가 사진에 반응하는 공통 패턴)

## 8. 기능 명세

### 기능 1. 사진 업로드 및 EXIF 자동 추출

**설명**: 사용자가 이미지 파일을 업로드하면 서버가 EXIF 메타데이터를 파싱해 카메라/렌즈/촬영값을 자동으로 채운다.

**Input**

- 이미지 파일: JPEG, HEIC, PNG (파일당 최대 25MB, 1회 최대 10장. 서버 처리 여유에 따라 조정)
- 업로더의 사용자 ID (로그인 세션)

**Output**

- 파싱된 EXIF 필드: 카메라 모델명, 렌즈 모델명(있는 경우), 초점거리, 조리개값(F), 셔터스피드, ISO, 촬영일시, GPS 좌표(있는 경우)
- 파싱 실패/누락 필드는 빈 값으로 표시하고 사용자가 수동 입력 가능한 상태로 미리보기 제공
- 카메라/렌즈는 EXIF 원문과 사용자가 확정한 표시명을 분리 저장 (기능 8 참고)

**특이사항**

- 렌즈 모델명은 카메라 제조사·펌웨어에 따라 EXIF에 기록되지 않거나 코드값만 남는 경우가 있어, 파싱 실패율이 브랜드별로 다를 수 있음
- 렌즈가 없는 고정 렌즈 카메라(X100VI, L10 등)는 렌즈 정보가 존재하지 않으므로, 카메라 모델만으로도 등록을 허용한다. 렌즈 정보가 없으면 사용자가 직접 입력할 수 있다.
- 스마트폰 사진은 위치정보 제공에 동의하지 않으면 GPS 필드 자체가 없음
- 인스타그램 등 SNS를 거쳐 재다운로드된 사진은 EXIF가 제거되어 있는 경우가 많음 (업로드 원본을 유도할 UX 필요)
- HEIC는 브라우저가 직접 표시하지 못하므로 서버에서 서빙용 JPEG/WebP로 변환하고 원본은 보관
- 서빙용 이미지에서는 EXIF의 GPS를 제거한다 (원본 파일에 좌표가 남으면 기능 3의 흐리기가 무의미해짐)

**수용 기준**

```
Given 사용자가 GPS와 렌즈 정보가 모두 포함된 JPEG 사진을 업로드했을 때
When 업로드가 완료되면
Then 카메라 모델, 렌즈 모델, 초점거리, 조리개, ISO, GPS 좌표가 자동으로 채워진 미리보기가 표시된다

Given 사용자가 렌즈/카메라 정보가 기록되지 않은 사진을 업로드했을 때
When EXIF 파싱이 완료되면
Then 렌즈 필드는 빈 값으로 표시되고 사용자가 직접 입력할 수 있다

Given 사용자가 고정 렌즈 카메라로 촬영한 사진을 업로드했을 때
When 렌즈 필드가 비어 있어도
Then 카메라 모델만으로 등록할 수 있다

Given 사용자가 EXIF가 전혀 없는 이미지(스크린샷 등)를 업로드했을 때
When 업로드가 완료되면
Then 모든 촬영 정보 필드가 빈 값으로 표시되고 사용자에게 수동 입력을 안내하는 메시지가 노출된다

Given 사용자가 HEIC 사진을 업로드했을 때
When 등록이 완료되면
Then 브라우저에서 표시 가능한 형식으로 변환된 이미지가 노출되고 원본은 보관된다
```

### 기능 2. GPS 없는 사진의 수동 위치 등록

**설명**: EXIF에 GPS 좌표가 없는 사진에 대해, 사용자가 지도 위에서 직접 위치를 지정할 수 있게 한다. 위치 지정은 필수이며 건너뛸 수 없다.

**Input**

- 사진 ID (기능 1에서 업로드된 사진)
- 사용자가 지도에서 클릭/드래그 또는 위치 검색으로 지정한 좌표(lat, lng)

**Output**

- 해당 사진에 위치 정보(lat, lng)가 저장됨
- 위치 정보 출처 플래그: `exif`(자동) 또는 `manual`(수동) 구분 저장

**특이사항**

- 수동 등록 좌표는 정확도가 사용자 기억에 의존하므로 EXIF 자동 등록보다 신뢰도가 낮을 수 있음 — 상세 페이지에서 "수동 등록" 배지 등으로 구분 표시하는 것을 고려
- 위치는 항상 저장하고 노출 여부는 공개 범위(기능 3)가 결정한다. 위치를 알리고 싶지 않은 사진은 "지도 미노출"을 선택하면 된다.

**수용 기준**

```
Given GPS 정보가 없는 사진을 업로드했을 때
When 사용자가 지도에서 특정 지점을 클릭하거나 위치 검색으로 지점을 지정하면
Then 해당 좌표가 사진의 위치로 저장되고 위치 출처가 "수동"으로 표시된다

Given GPS 정보가 없는 사진을 업로드했을 때
When 사용자가 위치 지정 단계에서 아무 지점도 선택하지 않고 다음 단계로 진행을 시도하면
Then 다음 단계로 진행할 수 없고 위치 지정이 필요하다는 안내가 표시된다
```

### 기능 3. 위치 공개 범위 설정 (프라이버시)

**설명**: 사진에 결부된 위치 정보를 어느 정도로 공개할지 사용자가 선택한다. 기본값은 `fuzzy`다.

**Input**

- 사진 ID
- 공개 범위 옵션 선택값: `exact`(정확한 좌표) / `fuzzy`(반경 흐리기, 기본값) / `hidden`(지도 미노출, 갤러리에만 노출)

**Output**

- 사진의 공개 좌표가 옵션에 따라 다르게 저장/노출됨
  - `exact`: 원본 좌표 그대로 노출
  - `fuzzy`: 원본 좌표를 중심으로 반경 500m 내 임의 좌표로 흐려서 노출. 반경은 고정이며 사용자가 선택하지 않는다. 오프셋은 **해당 사진에서 공개범위가 처음 `fuzzy`가 되는 시점(최초 등록이든, 이후 다른 값에서 변경이든)에 1회만 생성**해 고정 저장한다. 한 번 생성된 오프셋은 이후 `exact`/`hidden`으로 바꿨다가 다시 `fuzzy`로 돌아와도 재사용하며 재생성하지 않는다 (재생성이 반복되면 여러 시점의 노출 좌표 평균으로 원본이 역산될 수 있음). 오프셋 계산은 `PhotoVisibilityService`(서버)에서만 수행하고 클라이언트에는 절대 노출하지 않는다.
  - `hidden`: 지도에 핀을 표시하지 않고 갤러리(기능 8)에만 노출. 지역 필터 결과에서도 제외

**특이사항**

- 원본 좌표는 서버에 그대로 보관하되, 공개용 API 응답에서만 흐리기 처리하는 방식으로 구현해야 사용자가 나중에 공개 범위를 바꿔도 원본 정확도를 잃지 않음
- `hidden`은 집 등 사적인 장소에서 찍은 사진용이다. 위치는 저장하되 지도, 지역 필터, 상세 페이지의 위치 표시 등 모든 공개 응답에서 제외한다. 지도에서만 빠질 뿐 사진 자체는 갤러리와 프로필에 노출된다.
- 서빙하는 이미지 파일에서는 EXIF GPS를 제거한다 (기능 1 참고)
- 교외나 단독주택 지역처럼 500m 반경 안에 집이 적은 경우 `fuzzy`만으로는 특정될 수 있다. 업로드 화면에 "집이나 사적인 장소에서 찍은 사진은 흐리기 유지 또는 지도 미노출을 권장" 안내를 표시한다.
- 공개 범위는 사후에 변경할 수 있다. 이미 정확한 위치로 노출되었던 정보는 캐시나 스크린샷 등으로 회수할 수 없으며, 변경 화면에 이 사실을 안내한다.

**수용 기준**

```
Given 사용자가 위치 공개 범위를 "정확한 좌표"로 선택했을 때
When 다른 사용자가 지도에서 해당 핀을 조회하면
Then 원본 GPS 좌표 그대로 핀이 표시된다

Given 사용자가 위치 공개 범위를 "반경 흐리기"로 선택했을 때
When 다른 사용자가 지도에서 해당 핀을 조회하면
Then 원본 좌표가 아닌, 정해진 반경 내 임의의 좌표로 핀이 표시된다

Given 사용자가 위치 공개 범위를 "지도 미노출"로 선택했을 때
When 다른 사용자가 지도를 조회하거나 지역 필터를 적용하면
Then 해당 사진의 핀은 표시되지 않고, 갤러리에서는 조회된다

Given 사용자가 등록된 사진의 공개 범위를 변경했을 때
When 변경을 저장하면
Then 이후 조회부터 새 공개 범위가 적용된다
```

### 기능 4. 지도 탐색 및 필터링

**설명**: 사용자가 지도를 이동/줌하며 등록된 사진 핀을 탐색하고, 카메라/렌즈/지역 조건으로 필터링한다.

**Input**

- 지도 뷰포트(현재 화면에 보이는 좌표 범위)
- 필터 조건(선택): 지역, 카메라 브랜드/기종, 렌즈, 초점거리 범위, 조리개 범위, 월/계절

**Output**

- 뷰포트 내 조건에 맞는 사진 핀 목록 (줌 레벨이 낮을 때는 클러스터 단위로 묶어서 반환, 줌 레벨이 높아지면 개별 핀 좌표로 반환)

**특이사항**

- 핀이 밀집한 지역(예: 한강공원)에서는 클러스터링 없이는 렌더링 성능과 가독성이 떨어짐
- 필터 조건은 모두 AND로 결합한다.
- 클러스터링은 업계 일반값(radius 60px)을 따르고, 일정 줌 레벨(maxZoom 16) 이상에서는 개별 핀으로 표시한다.
- 지도 미노출(`hidden`) 사진은 지도 결과와 지역 필터에서 제외한다. 조회 조건 하나(`visibility <> 'hidden'`)로 처리되므로 데이터가 늘어도 비용이 커지지 않으며, 지도용 위치 인덱스를 이 조건의 부분 인덱스로 만들 수 있다.
- 시간대(일출/일몰/야경) 필터는 Phase 2다 (7-1 참고).

**수용 기준**

```
Given 지도에 100개 이상의 핀이 밀집한 지역이 있을 때
When 사용자가 낮은 줌 레벨로 해당 지역을 조회하면
Then 개별 핀 대신 개수가 표시된 클러스터 마커로 묶여서 표시된다

Given 사용자가 특정 카메라 기종으로 필터를 적용했을 때
When 지도가 갱신되면
Then 해당 기종으로 촬영된 사진의 핀만 표시된다

Given 사용자가 특정 렌즈와 초점거리 범위를 동시에 필터로 적용했을 때
When 지도가 갱신되면
Then 두 조건을 모두 만족하는 사진의 핀만 표시된다 (AND 조건)

Given 사용자가 적용한 필터 조건에 맞는 사진이 하나도 없을 때
When 지도가 갱신되면
Then 빈 지도 대신 "아직 이 조건에 맞는 사진이 없습니다" 안내가 표시된다
```

### 기능 5. 사진 상세 페이지

**설명**: 핀 또는 목록에서 사진을 선택하면 이미지와 EXIF 정보, 촬영자 정보를 함께 보여준다.

**Input**

- 사진 ID

**Output**

- 이미지, 카메라/렌즈/조리개/셔터스피드/ISO/촬영일시, 사용자 메모(사용자가 직접 적는 기타 정보), 위치(공개 범위에 따른 좌표, 지도 미노출이면 "위치 비공개" 표시), 촬영자 프로필 링크, 좋아요 수

**특이사항**

- 이미지는 원본 해상도를 유지하되 GPS를 제거한 서빙용 이미지로 제공한다. 로딩이 느려 문제가 되면 리사이즈된 버전을 제공한다. 지도 카드와 갤러리에는 썸네일을 사용한다.

**수용 기준**

```
Given 사용자가 지도에서 핀을 클릭했을 때
When 상세 페이지가 로드되면
Then 해당 사진의 이미지와 EXIF 정보, 촬영자 정보가 함께 표시된다

Given 사진의 위치 공개 범위가 "반경 흐리기"일 때
When 사용자가 해당 사진의 상세 페이지를 조회하면
Then 위치는 흐려진 좌표 기준으로 표시되고 "대략적 위치"로 안내된다

Given 사진의 위치 공개 범위가 "지도 미노출"일 때
When 사용자가 해당 사진의 상세 페이지를 조회하면
Then 위치 정보는 표시되지 않고 "위치 비공개"로 안내된다
```

### 기능 6. 회원가입 / 로그인

**설명**: 사용자가 사진을 업로드하거나 좋아요를 하기 위해 계정을 생성하고 로그인한다. 열람은 로그인 없이 가능하다.

**Input**

- 이메일/비밀번호 또는 소셜 로그인(카카오, 구글) 인증 정보

**Output**

- 인증된 사용자 세션(토큰)
- 사용자 프로필 레코드 생성(최초 가입 시). 보유 장비는 첫 업로드 시 확인받아 등록한다.

**특이사항**

- 인증은 NestJS에서 전부 처리하고, Next.js는 세션만 읽는다.

**수용 기준**

```
Given 신규 사용자가 이메일과 비밀번호로 가입을 시도했을 때
When 필수 입력값이 모두 유효하면
Then 계정이 생성되고 로그인 상태로 전환된다

Given 등록된 사용자가 잘못된 비밀번호로 로그인을 시도했을 때
When 인증에 실패하면
Then 로그인이 거부되고 오류 메시지가 표시된다

Given 사용자가 카카오 또는 구글 계정으로 로그인을 시도했을 때
When 인증이 성공하면
Then 계정이 없으면 생성되고 로그인 상태로 전환된다

Given 비로그인 사용자가 업로드를 시도했을 때
When 액션이 시도되면
Then 로그인을 요구하는 안내가 표시된다
```

### 기능 7. 좋아요

**설명**: 사용자가 사진에 좋아요를 남긴다. (저장/북마크는 Phase 2 — 7-1 참고)

**Input**

- 사진 ID
- 사용자 ID

**Output**

- 좋아요 상태 토글 결과
- 사진의 누적 좋아요 수 갱신

**수용 기준**

```
Given 로그인한 사용자가 사진 상세 페이지에서 좋아요를 누르지 않은 상태일 때
When 좋아요 버튼을 클릭하면
Then 좋아요 상태로 전환되고 좋아요 수가 1 증가한다

Given 로그인한 사용자가 이미 좋아요를 누른 상태일 때
When 좋아요 버튼을 다시 클릭하면
Then 좋아요가 취소되고 좋아요 수가 1 감소한다

Given 비로그인 사용자가 좋아요 버튼을 클릭했을 때
When 액션이 시도되면
Then 로그인을 요구하는 안내가 표시되고 좋아요는 반영되지 않는다
```

### 기능 8. 갤러리 (카메라/렌즈별 작례 보기)

**설명**: 지도와 같은 사진 DB에서 제조사/카메라/렌즈 컬럼을 기준으로 사진을 그리드 목록으로 보여준다. 위치 공개 범위와 무관하게(지도 미노출 사진 포함) 노출된다. 별도의 장비 스펙/소개 페이지는 만들지 않는다.

**Input**

- 필터(선택): 카메라 브랜드/기종, 렌즈, 초점거리 범위, 조리개 범위 (기능 4와 동일한 조건, AND 결합)
- 정렬: 최신순(기본) / 좋아요순
- 페이지 커서 (무한 스크롤)

**Output**

- 썸네일 그리드, 항목 클릭 시 사진 상세(기능 5)로 이동

**특이사항**

- 필터 조건과 API는 기능 4와 공유한다. 지도는 뷰포트+클러스터, 갤러리는 페이지네이션이라는 응답 방식만 다르다.
- 지역 필터는 지도에 노출되는 사진에만 적용된다 (지도 미노출 사진의 위치가 지역 필터로 유추되는 것을 막기 위함)
- EXIF의 카메라/렌즈 문자열은 제조사·펌웨어마다 표기가 달라("ILCE-7M4" vs "Sony A7 IV") 원문 그대로 필터하면 같은 장비가 갈라진다. MVP는 아래 방식으로 대응한다.
  - EXIF 원문(`camera_raw`, `lens_raw`)과 사용자가 확정한 표시명(`camera_name`, `lens_name`)을 분리 저장한다. 원문은 절대 버리지 않는다 (나중에 정규화를 소급 적용하기 위함).
  - 업로드 미리보기에서 EXIF 원문으로 입력란을 채우고, 입력 시 DB의 기존 표시명을 자동완성으로 제안한다. 기존 값을 고르면 통일되고, 없으면 새 장비로 등록된다.
  - 갤러리/지도 필터 선택지는 DB의 표시명 `DISTINCT` 목록에서 가져오므로 새 장비는 다음 조회부터 자동으로 나타난다.
  - 별칭 매핑과 마스터 DB는 Phase 2에서 도입한다 (7-1 참고).

**수용 기준**

```
Given 사용자가 갤러리에서 특정 카메라 기종으로 필터를 적용했을 때
When 목록이 갱신되면
Then 해당 기종으로 촬영된 사진만 표시되고, 지도 미노출 사진도 포함된다

Given 갤러리를 진입했을 때
When 정렬을 선택하지 않으면
Then 최신순으로 표시되고, 좋아요순으로 전환할 수 있다

Given 비로그인 사용자가 갤러리에 접근했을 때
When 목록을 열람하면
Then 로그인 없이 열람할 수 있다

Given 사용자가 DB에 없는 새 카메라 이름으로 사진을 등록했을 때
When 등록이 완료되면
Then 해당 이름이 다음 조회부터 갤러리와 지도의 필터 선택지에 나타난다

Given 사용자가 적용한 필터 조건에 맞는 사진이 하나도 없을 때
When 갤러리가 갱신되면
Then 빈 그리드 대신 "아직 이 조건에 맞는 사진이 없습니다" 안내가 표시된다
```

### 기능 9. 사진 신고 및 운영자 조치

**설명**: 사용자가 사진을 신고하면 운영자가 검토해 비공개/삭제 조치를 할 수 있게 한다. 위치 공개 범위(기능 3)는 업로더 본인의 좌표 정밀도를 조절하는 장치일 뿐, 사진 내용 자체(타인의 사생활, 얼굴, 차량 번호판 등)나 제3자 신고 대응은 다루지 않는다 — 이 공백을 신고 기능으로 메운다. 정보통신망법상 사생활 침해 신고에 대한 임시조치 근거(요청 시 비공개 처리)를 마련하는 목적도 있다.

**Input**

- 신고 대상 사진 ID
- 신고자 사용자 ID (로그인 필요)
- 신고 사유: `privacy`(사생활/위치 노출) / `inappropriate`(부적절한 콘텐츠) / `copyright`(본인 촬영물 아님) / `other`(기타, 직접 입력)

**Output**

- 신고 레코드 생성 (사진 ID, 신고자, 사유, 처리 상태: `pending`/`reviewed`/`actioned`)
- 운영자 조치 시 사진 상태 변경: 비공개(지도·갤러리 모두 미노출) 또는 삭제
- 신고자에게 접수 확인 안내

**특이사항**

- 신고 접수 즉시 자동으로 숨기지는 않는다(악용 방지). 운영자가 검토 후 조치한다.
- 동일 사진에 신고가 누적되면(예: 3건 이상) 운영자 검토 대기열에서 우선순위를 높인다.
- MVP 단계는 운영자가 직접 수동으로 검토하는 것으로 충분하다(사용자 수가 적음). 자동화된 모더레이션 도구는 Phase 2.
- MVP에는 운영자용 어드민 패널을 만들지 않는다. "운영자 검토"는 본인이 DB(Prisma Studio 등)에서 `reports` 테이블을 직접 조회하고 `photos.status`를 수동으로 바꾸는 것으로 처리한다. 별도 admin role/화면이 필요해지는 시점(제3자 운영자가 생길 때)에 재검토한다.
- 업로드 화면에 "타인의 사생활(얼굴, 차량 번호판, 남의 집 등)이 식별되는 사진은 피하거나 가려서 올려달라"는 안내 문구를 노출한다.

**수용 기준**

```
Given 로그인한 사용자가 특정 사진에서 신고 버튼을 눌렀을 때
When 신고 사유를 선택해 제출하면
Then 신고가 접수되고 신고자에게 접수 확인이 표시된다

Given 운영자가 신고된 사진을 검토해 비공개로 조치했을 때
When 다른 사용자가 지도/갤러리를 조회하면
Then 해당 사진은 더 이상 노출되지 않는다

Given 비로그인 사용자가 신고를 시도했을 때
When 액션이 시도되면
Then 로그인을 요구하는 안내가 표시되고 신고는 접수되지 않는다
```

|---|---|

| 보유 장비 | 필수. 첫 업로드 시 EXIF로 미리 채워 확인 |
| 지원 포맷 | JPEG, HEIC, PNG |
| 업로드 제한 | 파일당 25MB, 1회 10장 (서버 여유에 따라 조정) |
| 렌즈 정보 | 없어도 등록 가능 (고정 렌즈 카메라). 있으면 수동 입력 가능 |
| 위치 입력 | GPS 유무와 관계없이 필수, 건너뛰기 불가 |
| 위치 공개 범위 | `exact` / `fuzzy`(기본값, 500m 고정) / `hidden`(지도 미노출, 갤러리 노출) |
| 공개 범위 사후 변경 | 가능. 이미 노출된 정보는 회수 불가, 화면에서 안내 |
| 필터 결합 | 전부 AND |
| 클러스터링 | supercluster, radius 60px, maxZoom 16 이상은 개별 핀 |
| 이미지 노출 | 원본 해상도 유지(GPS 제거본), 느리면 리사이즈 적용 |
| 갤러리 | MVP 포함. 지도와 같은 DB와 필터 사용, 최신순/좋아요순 |
| 장비명 정규화 | MVP는 원문/표시명 분리 저장 + 자동완성, 별칭 매핑은 Phase 2 |
| 스택 | NestJS + Next.js(UI 전용) + PostgreSQL+PostGIS + Prisma + 카카오맵 + Cloudflare R2 |
| NestJS 모듈 구조 | 기능별 1:1이 아니라 소유권 기준 4개: Auth / Photos(1,2,3,5) / Discovery(4,8) / Engagement(7,9) |
| 세션 검증 | Next.js는 쿠키를 직접 검증하지 않고 매번 NestJS에 검증 요청 (`/auth/me`) |
| fuzzy 오프셋 | 처음 fuzzy가 되는 시점에 1회만 생성, 이후 재사용(재생성 금지). 서버(PhotoVisibilityService)에서만 계산 |
| 운영자(기능 9) 처리 | MVP엔 어드민 패널 없음. DB 직접 조회/수정으로 처리 |
| Phase 2 확정 | 시간대 필터, 같은 장소·다른 장비 비교, 추천 출사지, 저장(북마크), 장비명 별칭 매핑 |
| 신고/모더레이션 | MVP 포함(기능 9). 사용자 신고 + 운영자 수동 검토·비공개/삭제. 자동 모더레이션은 Phase 2 |
| 수익구조 | MVP에서 구현하지 않음. 기능 8(갤러리)을 장비별 랜딩페이지로 설계해 향후 제휴 링크(어필리에이트)를 끼우기 쉽게 구조만 열어둔다 |
