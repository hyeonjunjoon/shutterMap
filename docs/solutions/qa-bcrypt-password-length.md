# /qa에서 발견: bcrypt 72바이트 이후 비밀번호가 조용히 잘림

## 문제
서로 다른 두 비밀번호(앞 72바이트는 같고 그 뒤만 다름)로 각각 가입/로그인을 시도했는데, **둘 다 로그인이 성공**했다.

## 원인
bcrypt는 알고리즘 구조상 입력을 72바이트까지만 보고 그 뒤는 조용히 버린다. `RegisterDto`에 비밀번호 상한(`@MaxLength`)이 없어서, 72바이트 넘는 비밀번호도 그대로 받아 해시했다 — 결과적으로 "비밀번호의 뒷부분은 아무 의미가 없는" 상태였다.

## 해결책
`RegisterDto.password`에 `@MaxLength(72)` 추가 — 가입 시점에 72자 넘는 비밀번호를 400으로 거부한다.

(참고: `@MaxLength`는 문자 수 기준이고 bcrypt의 72는 바이트 기준이라, 한글/이모지처럼 멀티바이트 문자가 섞인 비밀번호는 72자가 되기 전에 72바이트에 먼저 도달할 수 있다. 지금은 72자 제한으로 충분히 보수적이라고 보고 넘어갔다 — 바이트 단위까지 정확히 하려면 `Buffer.byteLength`를 쓰는 커스텀 밸리데이터가 필요하다.)

## 다음 작업 전 체크할 것
- [ ] bcrypt(또는 비슷한 길이 제한이 있는 해시 함수)를 쓰는 **다른 비밀번호 입력 경로**(비밀번호 변경 등)를 추가하면, 거기에도 같은 `@MaxLength(72)`를 잊지 않고 넣는다.
- [ ] 한글 비밀번호를 실제로 많이 받게 되면, 문자 수 대신 `Buffer.byteLength(value, 'utf8') <= 72`로 검증하는 커스텀 밸리데이터로 올린다.
