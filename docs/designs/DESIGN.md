# DESIGN.md — ShutterMap

범위: 메인 색상/배경 톤, 폰트, radius 3가지만. 전체 디자인 시스템이 아니라 `web/` 프로젝트를 만들 때 바로 적용할 토큰 값과 그 이유만 적는다.

## 배경 / 색상

- **다크 모드가 기본, 라이트 모드는 보조.** 사진이 콘텐츠의 전부라, 배경이 밝으면 눈이 피로하고 사진의 톤이 왜곡돼 보인다.
- **배경은 완전 무채색(채도 0%)** — 웜/쿨 톤을 섞지 않는다. 라이트룸/포토샵의 뉴트럴 그레이 작업 배경과 같은 이유: 배경에 색온도가 있으면 그 위에 놓인 사진의 색 인식이 왜곡된다.
- **앰버(amber)는 포인트 컬러로만** — 버튼, 좋아요/선택 상태, 지도 마커. 배경/텍스트에는 쓰지 않는다. 블루/퍼플 SaaS 클리셰를 피하면서도 "조리개·골든아워"를 연상시키는 이 제품만의 포인트.
- 라이트 모드에서는 앰버를 더 어둡게(채도↑, 명도↓) 써서 흰 배경에서도 명암비를 확보한다.

## 폰트

- **본문/제목: Pretendard 한 패밀리.** 제목은 같은 폰트의 Black/ExtraBold 굵기로 위계를 준다 — 폰트 추가 로딩 없이 심플하게.
- **EXIF/숫자 데이터(조리개·초점거리·ISO·셔터스피드): IBM Plex Mono 확정.** 장비 스펙을 표처럼 정렬해서 보여주는 게 이 제품의 핵심 콘텐츠라, 일반 산세리프보다 모노스페이스가 "스펙표" 느낌을 살리고 실제로도 숫자 정렬에 유리하다. `tabular-nums`를 항상 같이 적용해서 숫자 폭을 고정한다(자리수가 바뀌어도 레이아웃이 흔들리지 않음).

## Radius

- **UI 요소(버튼/카드/인풋/다이얼로그): 8px.** shadcn 기본값, 각지면 차갑고 너무 둥글면 소셜앱 느낌이라 중간값.
- **사진 썸네일/이미지: 2px.** UI radius와 분리된 별도 토큰. 사진 자체는 콘텐츠이므로 거의 각진 상태를 유지하되, 레티나 디스플레이에서 완전 직각 모서리가 주는 날카로운 느낌만 살짝 깎는다.

## 적용 방법 (`web/` 스캐폴드 시)

1. `docs/designs/globals.css`의 내용을 `web/app/globals.css`에 그대로 복사한다.
2. **다크 모드가 기본값**이라 `:root`에 다크 토큰을, `.light`에 라이트 오버라이드를 넣는 구조로 되어 있다 (보통의 `.dark` 오버라이드 구조와 반대). `next-themes`를 `defaultTheme="dark"`로 설정하고, 라이트 모드 전환 시 `.dark`가 아니라 `.light` 클래스를 토글한다.
3. `--radius`(UI)와 `--radius-photo`(이미지)는 shadcn 표준 변수가 아닌 이 프로젝트의 추가 토큰이다 — `tailwind.config`의 `borderRadius`에 `photo: 'var(--radius-photo)'`로 등록해서 `rounded-photo` 유틸리티로 쓴다.
4. EXIF 숫자 표시 컴포넌트에는 `font-mono tabular-nums` 클래스를 같이 적용한다.
